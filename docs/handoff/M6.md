# Handoff notes — M6

Historical M6 handoff for version `1.1.1`, targeting **1.8.9 / protocol 47**. The implementation is
covered by unit tests. The live action scenarios and 50k-node p99 benchmark were not run. The M4
anti-cheat soak and M7 50-bot soak also remain outstanding; none of these roadmap gates is marked
complete here.

The implementation provides the features listed below, subject to the limitations recorded here
and in the current [roadmap](../ROADMAP.md).

## Invariants the next milestone may rely on

- Actions write movement/look controls through `Lease.controls` and its `look()`/`jump()` delegates;
  revoked leases raise `LeaseRevoked`. Direct Bot movement methods remain available separately.
- Resource acquisition is all-or-nothing. Conflicts raise `ActionBusy` unless `queue=True`; queued
  actions never preempt. Higher priority preempts only when `preempt=True` and not queued.
- Preemption is cooperative: the holder's task is cancelled, `on_preempted` and `checkpoint` run,
  controls are zeroed and the lease is released. `ABORT` rejects the old handle with
  `ActionPreempted`; `RESUME` restores and reruns; `REQUEUE` starts over.
- `lease.critical()` defers preemption while a multi-packet operation is in flight. The scheduler
  waits up to `max_critical_s` (1 s) before forcing revocation; `preempt_grace` (150 ms) bounds
  cleanup.
- `ActionScheduler.run()` returns immediately. The handle is awaitable, supports multiple waiters,
  and distinguishes user cancellation (`ActionCancelled`) from timeout (`ActionFailed`).
- The death barrier (`set_barrier(True)`) cancels current work and blocks new starts until
  `release_barrier()`. `Bot` wires death/respawn and cancels actions on close/disconnect.
- `PathPlanner.plan` takes one immutable snapshot and runs A* off-loop; `plan_sync` is for tests.
  `NoPath` carries the best partial path in `exc.fields["partial"]`.
- A* never traverses unknown states or unloaded chunks, never cuts corners, and treats lava/fire/
  cactus/magma/berry/powder snow as hazards. Ties are deterministic.
- `PathExecutor` only writes through the lease and awaits `PhysicsTickEvent`; it stops controls on
  completion/failure and fails after `stuck_ticks`/`max_ticks_per_node`.
- `GoTo` is `MOVEMENT | LOOK`, `RESUME`, and checkpoints only its goal. `bot.actions.goto` defaults
  to `Priority.WORK`.
- `SurvivalMonitor` eats at `SURVIVAL` when health ≤ `threshold` (6.0) and food is available; the
  bot starts it on join and stops it on close/disconnect.

## Fixed while verifying M6

- `Lease.look`/`Lease.jump` were called by actions but did not exist; both now delegate to
  `controls`.
- The scheduler emitted `int(Resource)`, which fails for a plain `enum.Flag`. It now emits
  `Resource.value`.
- The preemption busy-wait used the injected clock, which `FakeClock` never advances on its own.
  It now waits on an event set when preemption finishes.
- `queue=True` previously still preempted; queued submissions now wait for the holder.

## Deferred / limitations

- No live anti-cheat verification of dig/place/equip/goto; server rejections surface as
  `ActionFailed` from the host call.
- Inventory transactions are two clicks with no rollback; a rejected click can desync the expected
  slot.
- Pathfinding does not model swimming, boats, parkour, or re-plan on world changes mid-path.
- No jump-physics lookahead; `PathExecutor` requests jumps one tick at a time.
- Path cache invalidation is delegated to `swarm.PathCache` and its world version.
- `GoalInvert` has a zero heuristic and can consume the whole node budget.
